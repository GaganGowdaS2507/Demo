# RNSharedApp — Face Recognition Playground (merged)

This project is `RNSharedApp` (the app shell, with real native `android/` and
`ios/` projects) with the **Face Recognition Playground** feature — offline,
model-agnostic face detection/recognition benchmarking — merged into it.

Everything in this repo targets **React Native 0.74.5 / React 18.2.0**, the
version the native projects were generated with. The original
FaceRecognitionPlayground was written against RN 0.86 / React 19 with a
Nitro-Modules-based TFLite binding and no real native project; all of that
has been ported down/back to 0.74-compatible equivalents (details below).
Everything has been verified with `tsc --noEmit` (clean) and `jest` (12/12
tests passing, including a full-tree render smoke test of `App.tsx`).

## What changed vs. the original FaceRecognitionPlayground

`react-native-fast-tflite`'s v2 API differs slightly from the v3/Nitro API
the original code was written against — `TFLiteModelLoader.ts` was updated
accordingly:

- The exported type is `TensorflowModel`, not `TfliteModel`.
- `loadTensorflowModel(source, delegate?)` takes a single delegate **string**
  (`'default' | 'metal' | 'core-ml' | 'nnapi' | 'android-gpu'`), not an array
  — omitted here to use the default CPU delegate.
- `model.run(inputs)` accepts and returns `TypedArray[]` (e.g.
  `Float32Array[]`) **directly** — no more manual `ArrayBuffer` conversion,
  which actually simplifies the loader vs. the original Nitro-based code.

No other application code (screens, hooks, database, embedding/similarity
math, navigation) needed changes — none of it used React-19-only APIs or
touched Nitro Modules directly.

## What was merged in from RNSharedApp (the base)

- Real native `android/` and `ios/` projects (Gradle, Xcode project, Podfile,
  Gemfile, `MainActivity`/`MainApplication`, `AppDelegate`) generated by the
  React Native 0.74.5 CLI — the FaceRecognitionPlayground repo shipped
  without one of these (its own README says to regenerate one).
- App identity (`RNSharedApp` package/bundle id, component name) is kept as-is
  since it's compiled into `MainActivity.kt` / `AppDelegate.mm`; only the
  user-facing display name/label was updated to "Face Recognition
  Playground".

## Native project changes made for this merge

**Android** (`android/`):
- `AndroidManifest.xml`: added `CAMERA`, `READ_MEDIA_IMAGES` (API 33+) and
  `READ_EXTERNAL_STORAGE` (API ≤32) permissions for `react-native-image-picker`
  / `react-native-fs`, plus the `com.google.mlkit.vision.DEPENDENCIES=face`
  meta-data tag so ML Kit's on-device face model bundles at install time
  (fully offline, no first-run download).
- `build.gradle`: `minSdkVersion` raised **23 → 24**, required by
  `react-native-fast-tflite` and `onnxruntime-react-native`.
- `android/app/src/main/assets/models/`: placeholder folder for `.tflite` /
  `.onnx` model files (see its own README) — excluded from git via
  `.gitignore`, add your own model binaries here before building.
- New Architecture stays **disabled** (`newArchEnabled=false`, RNSharedApp's
  existing default) for maximum compatibility with this dependency set.

**iOS** (`ios/`):
- `Info.plist`: added `NSCameraUsageDescription`,
  `NSPhotoLibraryUsageDescription`, `NSPhotoLibraryAddUsageDescription` for
  `react-native-image-picker`; updated `CFBundleDisplayName`.
- Deployment target (13.4, from the RN 0.74 template) is unchanged and is
  sufficient for every dependency above.

## App-level changes

- `App.tsx`, `src/` (screens, hooks, `core/` business logic), `scripts/`, and
  the `__tests__/` logic tests came from FaceRecognitionPlayground as-is.
- `metro.config.js`: merged to add `tflite` / `onnx` / `ort` / `db` asset
  extensions (so model files can be `require()`d for debug tooling; the
  primary load path is still the native `assets/models/` folder).
- `jest.config.js` / `jest.setup.js`: rewritten to mock every native module
  the app tree touches (SQLite, AsyncStorage, ML Kit, fast-tflite,
  onnxruntime, Skia, RNFS, image-editor/resizer, image-picker, Slider) plus
  the official mocks shipped by `react-native-gesture-handler` and
  `react-native-safe-area-context`, so `App.tsx` can be rendered headlessly
  under Jest. `__tests__/App.test.tsx` is a full-tree render smoke test.
- `tsconfig.json`: FaceRecognitionPlayground's version (adds unused-but-handy
  `@core/*` etc. path aliases; app code currently uses relative imports, so
  this is purely additive).
- `package.json`: merged dependency set above; `name` stays `RNSharedApp` to
  match the native project's compiled-in component name.

## Setup

```bash
npm install
# iOS only:
cd ios && bundle install && bundle exec pod install && cd ..
```

1. Add your `.tflite` / `.onnx` model files to
   `android/app/src/main/assets/models/` (see that folder's README) and
   register them in `src/core/config/ModelCatalog.ts`.
   - iOS also needs the same model files added as bundle resources in Xcode
     (drag them into the `RNSharedApp` target, "Copy items if needed").
2. Run:
   ```bash
   npm run android
   # or
   npm run ios
   ```

## Verification performed on this merge

- `npx tsc --noEmit` — clean, no errors.
- `npx jest` — **3 suites / 12 tests passing**: `EmbeddingUtils.test.ts`,
  `SimilarityCalculator.test.ts` (pure-logic tests, unchanged from the
  original), and `App.test.tsx` (new — renders the entire merged component
  tree: `GestureHandlerRootView` → `SafeAreaProvider` →
  `RecognitionEngineProvider` → bottom-tab `RootNavigator` with all five
  screens).
- `npm install` with strict (non-legacy) peer dependency resolution —
  resolves with zero `ERESOLVE` conflicts across the full merged dependency
  tree.

What could **not** be verified in this environment (no Android SDK/Xcode
available): an actual Gradle/Android build or Xcode/CocoaPods build, and
on-device inference. Model binaries are also not included (see the
`assets/models/README.md`) — you'll need to supply your own `.tflite`/`.onnx`
files matching `ModelCatalog.ts` before running recognition end-to-end.
