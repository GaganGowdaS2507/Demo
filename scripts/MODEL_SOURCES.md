# Getting real model weights

The three files currently in `android/app/src/main/assets/models/` were
generated by `scripts/generate_placeholder_models.py` — they have the
correct tensor names/shapes for each `ModelCatalog.ts` entry, but random
weights, so the app runs end-to-end but produces meaningless embeddings.
Replace them with real weights from the sources below.

---

## 1. `mobilefacenet.tflite`
Catalog entry: `mobilefacenet-tflite-v1` · input `input` `[1,112,112,3]` float32 · output `[1,192]` float32

Source: **sirius-ai/MobileFaceNet_TF** (TensorFlow implementation + pretrained
checkpoint under `arch/pretrained_model`).
- Repo: https://github.com/sirius-ai/MobileFaceNet_TF

Convert the frozen graph to TFLite:
```bash
tflite_convert \
  --output_file mobilefacenet.tflite \
  --graph_def_file MobileFaceNet_9925_9680.pb \
  --input_arrays "input" \
  --input_shapes "1,112,112,3" \
  --output_arrays embeddings \
  --output_format TFLITE
```
Copy the result to `android/app/src/main/assets/models/mobilefacenet.tflite`.
(Note: the graph's output tensor is named `embeddings`; that's fine —
`TFLiteModelLoader.ts` reads the output positionally, not by name.)

---

## 2. `arcface_r100.onnx`
Catalog entry: `arcface-r100-onnx-v1` · input `data` `[1,3,112,112]` float32 (BGR) · output `fc1` `[1,512]` float32

Source: **OpenVINO Open Model Zoo — `face-recognition-resnet100-arcface-onnx`**
(an MXNet ResNet100/ArcFace model already converted to ONNX, with the exact
`data`/`fc1` tensor names the catalog expects).
- Model page: https://docs.openvino.ai/2023.3/omz_models_model_face_recognition_resnet100_arcface_onnx.html
- Also listed in InsightFace's own model zoo (`R100`, MS1MV2, ArcFace):
  https://github.com/deepinsight/insightface/blob/master/model_zoo/README.md

This one is already ONNX — no conversion needed, just download and place it
at `android/app/src/main/assets/models/arcface_r100.onnx`. Expect ~250MB
(fp32). If you need the smaller int8 footprint mentioned in the catalog
notes (~65MB), quantize with `onnxruntime.quantization.quantize_dynamic`.

---

## 3. `facenet_int8.tflite`
Catalog entry: `facenet-tflite-v1` · input `input` `[1,160,160,3]` float32 · output `[1,128]` float32

Source: **davidsandberg/facenet**, model `20170512-110547` (the 128-d
CASIA-WebFace checkpoint — note the newer `20180402-114759` checkpoint
outputs 512-d, not 128-d, so it will NOT match this catalog entry).
- Repo: https://github.com/davidsandberg/facenet
- Checkpoint: linked from the repo README under "Pre-trained models"

Steps:
```bash
# 1. Freeze the checkpoint to a .pb graph (facenet repo provides freeze_graph.py)
python src/freeze_graph.py ~/models/facenet/20170512-110547 20170512-110547.pb

# 2. Convert to TFLite with post-training int8 quantization (representative
#    dataset = a folder of ~100 aligned 160x160 face crops)
python - <<'PY'
import tensorflow as tf

def representative_dataset():
    import glob, cv2, numpy as np
    for path in glob.glob("calibration_faces/*.jpg"):
        img = cv2.imread(path)
        img = cv2.resize(img, (160, 160)).astype("float32")
        img = (img - 127.5) / 128.0
        yield [img[None, ...]]

converter = tf.lite.TFLiteConverter.from_frozen_graph(
    "20170512-110547.pb", input_arrays=["input"], output_arrays=["embeddings"],
    input_shapes={"input": [1, 160, 160, 3]},
)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.representative_dataset = representative_dataset
tflite_model = converter.convert()
open("facenet_int8.tflite", "wb").write(tflite_model)
PY
```
Copy the result to `android/app/src/main/assets/models/facenet_int8.tflite`.

---

## After replacing any file
No code changes are needed — `ModelCatalog.ts` already points at these
filenames. Just rebuild:
```bash
npx react-native run-android
```
